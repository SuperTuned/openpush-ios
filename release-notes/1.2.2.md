# OpenPush iOS SDK 1.2.2

First public release.

- Push registration: APNs token forwarding, notification permission (including
  provisional authorization), opt-in and opt-out, and a live push subscription
  accessor with change observers.
- Identity and targeting: external ID login with optional identity
  verification, tags, aliases, and custom events for journeys.
- Phone numbers (SMS and WhatsApp) with phone-code verification, and email
  addresses.
- In-app messages: fetch, triggers, presentation, click and lifecycle
  listeners, and persisted redisplay state.
- Notification Service Extension handler: action buttons (each with an
  optional link), rich media attachments, badge increments, and delivery
  receipts, plus a mode that shares an existing extension with another sender.
- Launch URLs open on tap by default, with a code switch and an `Info.plist`
  key to turn that off.
- Live Activities: token observation, push-to-start, and widget click
  tracking, in an extension-safe product.
- VoIP pushes through PushKit in a separate `OpenPushVoIP` product.
- An opt-in compatibility layer for apps migrating from another push SDK, with
  a migration guide and a migrated sample app.
- `openpush-ios-setup`, a command-line tool that adds OpenPush to an existing
  Xcode project and reuses its push setup.

## Upgrading from 1.1.x/1.2.x

Upgrading needs no code change: every public member keeps its signature, and the device
credential, subscription and queued events carry over.

- `register(token:externalID:)` is deprecated (a compiler warning, same signature): a non-empty
  `externalID` is now applied as `login(externalId:)` without an auth hash before the token is
  registered, so an identity is only ever attached through login. Use `login(externalId:authHash:)`
  and `register(token:)`.
- Assigning `currentToken` is deprecated: forward tokens with `register(token:)` or
  `didRegisterForRemoteNotifications(deviceToken:)`. An assigned token is now registered (after
  `initialize`) instead of only being stored; reading `currentToken` is unchanged.
- Observers, listeners and completions run on the main thread, always posted to the main queue,
  so a callback never runs inside the call that caused it, and in the order the SDK raised them.
  Click and foreground listeners still run inline inside `processClick` and `processForeground`,
  and `onLog` on the thread that wrote the line. Do not block the main thread waiting for a
  callback.
- `DeviceCredentialStore` keeps the device credential with
  `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` and updates it in place. A credential an
  earlier build stored is read and moved to that class the first time it is loaded, with the same
  value, so the device keeps its subscription. A credential is no longer carried to a different
  device through a backup; that device registers as a new install.
- As before, the SDK asks iOS for a push token only once notification permission is granted
  (fully or provisionally). Until then there is no token and so no subscription: no in-app
  messages, no Live Activity tokens, and no custom events attributed to this install. Explain
  what notifications are for before calling `requestPermission`.
- Custom events and Live Activity requests back off on the registration retry schedule instead
  of retrying every 2 or 30 seconds, and the custom event queue keeps at most 500 events. Events
  already queued on a device keep their stored format and still send.
- The privacy manifests now also declare email addresses, phone numbers, product interaction and
  the App Group reason for the shared `UserDefaults` suite.
